## 폰트 처리 결과

- Pretendard는 이 Figma 세션에서 사용할 수 없다. `figma.loadFontAsync`가 Pretendard Light/Regular/Bold 모두 실패했고, `listAvailableFontsAsync`에도 Pretendard가 0건이다.
- 기존 텍스트 스타일 12개의 폰트를 API로 읽으면 여전히 Inter(Light/Regular/Bold)다. 작업자가 Pretendard로 바꿔 두었다고 했지만 이 세션에서는 반영되어 보이지 않는다.
- 따라서 새 텍스트 전부에 기존 텍스트 스타일(`typography/…`)을 적용했고, 폰트는 스타일이 가진 Inter로 그려졌다. 이번에 새로 만든 모든 텍스트가 이에 해당한다: 새 컴포넌트 10개 안의 텍스트와 새 프레임 4개의 모든 텍스트. 글자 폭은 Pretendard와 달라 실제 폰트 적용 후 줄바꿈 위치가 달라질 수 있다(특히 체크리스트 6번 행은 Inter 기준으로 한 줄에 맞췄다).
- 굵기 대응은 skill-library와 같다: Light=300, Regular=400, Bold=700. design-export.json의 font_weight는 Inter 스타일 이름을 이 값으로 옮긴 것이다. 스타일의 폰트가 Pretendard로 바뀌면 텍스트가 자동으로 따라온다.

## 새 컴포넌트 (섹션 "Components / asset-review", 12:116)

색·모서리·좌우 패딩·간격은 기존 변수에 바인딩했고 텍스트는 기존 텍스트 스타일을 썼다. 컴포넌트 속성(TEXT prop)은 만들지 않고 인스턴스 안의 텍스트를 직접 덮어썼다(skill-library와 같은 방식).

1. badge-status (12:127, 변형 Status=임시저장/검수 대기/수정 요청/승인됨/반려). 색 구분 없이 단색 위계로만 구분: 임시저장=흰 채움+hairline 테두리+muted 글자, 검수 대기=canvas-soft 채움+ink 글자, 수정 요청=흰 채움+ink 테두리+ink 글자, 승인됨=ink 채움+흰 글자, 반려=muted(#707070) 채움+흰 글자. accent 미사용.
2. button-primary-disabled (12:128). button-primary와 같은 형태에서 채움을 field, 글자를 text-faint로 바꾼 비활성 버튼. 기존 button-primary는 변형 세트로 바꾸지 않았다(기존 화면의 인스턴스를 건드리지 않으려고). 아래 "임의로 정한 부분" 참고.
3. checkbox-row (12:155, 변형 Kind=Item/Required/All × State=Unchecked/Checked, 6개). Required는 기존 badge-permission(Kind=paid) 인스턴스에 "필수"를 넣었다. All은 "전체 확인" 행(canvas-soft 채움, 굵은 글자).
4. radio-option (12:167, 변형 State=Selected/Default). 선택 원(ink 링 + 점), 옵션 이름, 한 줄 설명.
5. radio-group (12:199, 변형 Options=2/3). "공개 범위" 라벨 + radio-option 인스턴스 2개(비공개, 멤버 공개) 또는 3개(+ 판매 신청). 첫 옵션 "비공개"가 Selected.
6. field-file-attach (12:200). 라벨 + field 채움 첨부 영역.
7. field-textarea (12:207). 라벨 + 멀티라인 입력(높이 96).
8. field-price (12:211). 라벨 + 가격 입력(단위 "원").
9. asset-card (12:216). 자산 이름 + 상태 배지(badge-status 인스턴스) + 메타 2줄. 내 자산 목록과 운영자 검수 대기 목록에 함께 쓴다.
10. bottom-bar (12:235, 변형 Kind=form/review). form은 임시저장(button-outline) + 등록(button-primary), review는 승인(button-primary-disabled) + 수정 요청·반려(button-outline). 위 테두리 hairline-soft, 패딩 16/16/32/16.

10개(변형 세트 5개: badge-status, checkbox-row, radio-option, radio-group, bottom-bar / 단일 5개)다. 요청한 항목(파일 첨부, 멀티라인 입력, 가격 입력, 라디오 옵션 그룹, 체크박스 행, 자산 목록 카드, 상태 배지 5종, 하단 고정 버튼 영역, 비활성 버튼)을 모두 만들었고, 라디오는 옵션(radio-option)과 그룹(radio-group) 두 개로 나눠 만들었다. 기존 컴포넌트는 button-pill-soft(뒤로), button-outline, button-primary, chip, text-input, badge-permission을 재사용했고 복제하지 않았다.

만들지 않은 것: 설계 §11의 A4(진행 표시), A6(상태 필터), A12(바텀시트)는 채택 여부가 정해지지 않아 만들지 않았다. A10(펼침 영역)도 만들지 않았다.

## design-export.json

- 노드 수: 프레임 4개 합계 198개 = 36(유료 회원) + 75(판매 승인 회원) + 32(대기 목록) + 55(상세와 체크리스트).
- 값은 최종 프레임의 Figma 노드를 use_figma로 순회해 읽은 값이다(색은 변수 해석값의 hex, 굵기는 폰트 스타일 이름 매핑, 모서리, 그림자 개수, auto-layout 패딩·간격). 스크립트 출력에서 노드를 파일로 옮긴 뒤, 프레임별 노드 수와 FNV 해시를 Figma 쪽 결과와 대조해 4개 프레임 모두 일치함을 확인했다.
- 최상위 screens 3개는 spec의 JSON 블록에서 그대로 복사했다. 프레임 screen 값은 "내 자산 등록"(2개) 또는 "운영자 검수"(2개)다. 내 자산 등록 프레임 두 개에는 spec의 variant 값(paid, seller)을 `variant` 필드로 추가했다. 프레임마다 `name`, `figma_node`도 있다.
- 포함 기준은 skill-library와 같다: 채움 또는 테두리가 있는 프레임/인스턴스와 모든 텍스트 노드. 숨긴 노드(유료 회원 프레임 제목 입력의 검색 아이콘)는 뺐고, 벡터·사각형·배치용 프레임은 뺐다.
- kind: 텍스트=text, 버튼(button-*)=button, chip/badge-*=badge, text-input/field-*/입력 컨트롤 프레임=input, asset-card/checkbox-row/radio-option=card, bottom-bar=bottom-bar, 체크박스와 라디오의 원·점=toggle. 새 컴포넌트의 kind는 위처럼 정했다(임의).
- 추출값 점검: 굵기 400/700, 모서리 0/16/24/9999, 그림자 0, 글자 간격 0, 패딩·간격 0/4/8/12/16/32, accent 0곳.
- MVP 제외 단어 검사: 프레임 텍스트에서 "허들링 픽", "피드백", "수익", "판매 중", "판매 중지"는 0회, "구매"는 체크리스트 8번 원문 "구매자가 바로 써볼 수 있는 것"에서만 나온다.

## 임의로 정한 부분

- 기존 button-primary(단일 컴포넌트)를 변형 세트로 바꾸지 않고 별도 컴포넌트 button-primary-disabled로 만들었다. 기존 화면 인스턴스를 건드리지 않기 위해서다. "button-primary의 비활성 변형"이 꼭 같은 세트 안의 변형이어야 하면 나중에 합칠 수 있다.
- 비활성 버튼 모양: field(#ececec) 채움 + text-faint 글자.
- 상태 배지 5종 구분: 임시저장=아웃라인(연한) · 검수 대기=soft 채움 · 수정 요청=진한 아웃라인 · 승인됨=ink 채움 · 반려=muted 채움. 반려에 muted 채움을 쓴 것은 ink와 구분하려는 선택이다.
- 공개 범위 옵션 설명 문구(PRD에 없음): 비공개 "나만 볼 수 있어요.", 멤버 공개 "멤버에게 공개돼요.", 판매 신청 "운영자 검수를 거쳐 판매를 신청해요."
- 하단 버튼 문구: 폼은 "임시저장"(보조) + "등록"(주). 판매 승인 회원 화면에서도 같다(임시저장 → 검수 요청 문구는 설계에 이름이 없어 쓰지 않았다).
- 체크박스와 라디오 표시는 원형(모서리 9999)으로 했다. 사각 체크박스는 모서리 값 규칙(0/16/24/9999)에서 24px 크기에 맞는 값이 없어서다. 체크박스 행의 세로 패딩은 4, 가로는 12로 줄여 8개 + 전체 확인 행 + 가격 입력이 한 화면에 들어가게 했다. 행 높이는 32~38이라 터치 영역이 44보다 작다.
- 체크리스트 행 글자는 body-sm(13), "전체 확인" 행은 link(15/700)로 했다. 6번 행이 "필수" 배지 때문에 한 줄에 들어가게 하려는 선택이다(Inter 기준).
- 정보 3줄은 카드 없이 "라벨 + 값" 줄로 두었다(설명, 첨부 파일, 사용 방법의 값 문구는 예시 텍스트). 가격 승인 입력은 field-price를 재사용해 라벨을 "가격 승인", 값을 "30,000"(ink)로 바꿨다. 통화·형식은 PRD에 없어 "원" 단위, 천 단위 쉼표로 정했다.
- 제목 입력은 기존 text-input에서 검색 아이콘만 숨기고 placeholder를 바꿔 썼다(새 컴포넌트를 더 만들지 않기 위해).
- 분류 칩은 4개가 한 줄에 들어가지 않아 줄바꿈(wrap)으로 두 줄에 놓았다.
- 화면 위쪽 여백은 skill-library와 같이 64(spacing/section-lg)로 했고, 화면의 스크롤은 body 프레임의 clip으로 표현했다.
- 새 화면 프레임은 x=1400~3200, y=1500에 나란히 두었다(기존 화면 3개는 x=0~1330).
- 목록 예시 텍스트(자산명, 제작자, 날짜, 코멘트 예시)는 모두 임의의 더미 문구다.

## 재내보내기: text·variant 필드 추가

- 판정 스크립트의 프레임 검사(FRM-1~4)가 읽는 필드를 design-export.json에 추가했다. 기존 노드 구성(포함 기준, id, kind, 값)은 그대로다. Figma 파일은 읽기만 했다.
- 추가한 필드: 텍스트 노드(kind "text")의 `text`(characters 값), 변형 세트에 속한 컴포넌트 인스턴스의 `variant`(mainComponent가 속한 컴포넌트 세트의 variantProperties). 변형 속성이 없는 단일 컴포넌트(button-*, text-input, asset-card 등)에는 생략했다.
- 값은 use_figma로 프레임 4개를 각각 순회해 읽은 출력을 프레임별 파일로 저장한 뒤 스크립트로 병합했다. 병합 때 export의 component 이름과 Figma 컴포넌트(세트) 이름이 모든 인스턴스에서 일치하는지 대조했고, 병합 전 노드 필드가 하나도 바뀌지 않았음을 원본과 비교해 확인했다.
- 확인 결과: 프레임별 노드 수 36/75/32/55 (합계 198, 변동 없음). text 노드 116개 전부에 `text` 채움. variant 채운 노드 38개(badge-status 11, checkbox-row 9, chip 8, radio-option 5, bottom-bar 3, badge-permission 2). radio-option 5개, checkbox-row 9개 모두 variant 있음.
