# 화면 설계: 스킬 라이브러리

근거: PRD §5, §6-3, §7, §9, §16 / 분석 문서 A1~A7

## 1. 화면 목적

하이서가 만든 검증된 스킬·프롬프트를 카드 형태로 찾아보고, 상세에서 복사하거나 파일로 받아 쓰게 하는 화면이다 (PRD §6-3). 정보 구조상 "스킬 라이브러리" 섹션에 해당한다 (PRD §5). MVP 1차 필수 포함 항목이다 (PRD §9).

## 2. 사용 역할

| 역할 | 접근 | 근거 |
|---|---|---|
| free (무료 회원) | 사용. 샘플 프롬프트 사용, 유료 자료 미리보기 범위 | PRD §7-2 |
| paid (유료 회원) | 사용. 전체 스킬/프롬프트 일부 또는 전체 접근 | PRD §7-3 |
| seller (승인 회원) | 사용. 유료 회원 권한 전체를 가짐 | PRD §7-4 |
| guest (비회원) | 이 화면을 보지 않는다 (작업자 확정). roles에서 뺀다. | 작업자 확정 |
| admin (운영자) | 이 화면을 보지 않는다 (작업자 확정). roles에서 뺀다. | 작업자 확정 |

## 3. 화면 구성 (위에서 아래로)

1. 검색창 (화면 상단). PRD §6-3 필수 2, 분석 A1·A2.
2. 필터 영역 (검색창 바로 아래). 태그·카테고리를 고르는 가로 스크롤 칩 줄과, 추가 조건용 드롭다운형 필터. PRD §6-3 필수 3, 분석 A2.
3. 스킬 카드 목록 (세로로 쌓임). PRD §6-3 필수 1, 분석 A1.
4. 카드 한 장을 누르면 스킬 상세로 들어간다.
5. 검색·필터 결과가 없을 때의 빈 화면 안내 (제안, 아래 §7 참고).

### 3-1. 스킬 상세 (카드에서 진입)

- 상세는 탭 또는 구역으로 나눈다: 사용 정보(언제 쓰나요, 준비물, 사용 순서, 주의할 점), 프롬프트 또는 파일, 예시 결과. PRD §6-3 필수 6, 분석 A5.
- 화면 하단에 고정 버튼 영역을 두고 "복사"와 "파일 다운로드"를 둔다. PRD §6-3 필수 4·5, 분석 A4.
- 관련 미션을 카드형 링크로 보여주고, 누르면 미션 화면으로 이어진다. PRD §6-3 필수 8, 분석 A6.

## 4. 카드에 들어가는 항목 (PRD §6-3 카드 항목 기준)

PRD §6-3은 카드에 최소한 아래 12개 정보가 필요하다고 정한다. 작업자 확정에 따라 목록 카드에는 스킬명, 카테고리, 난이도, 권한 배지(무료/유료/코호트)만 올리고, 나머지는 상세 화면에 둔다.

| 항목 | 배치 | 비고 |
|---|---|---|
| 스킬명 | 목록 카드 | A1 |
| 카테고리 | 목록 카드, 태그 형태 | A1 |
| 난이도 | 목록 카드, 카테고리 태그 옆 작은 태그 | A3, PRD 필수 7 |
| 권한 (무료 / 유료 / 특정 코호트 전용) | 목록 카드, 권한 배지(무료/유료/코호트). 아래 §5 참고 | PRD §6-3 카드 항목 |
| 추천 대상 | 상세 | 목록 카드에는 올리지 않음 |
| 사용 도구 | 상세 | 목록 카드에는 올리지 않음 |
| 언제 쓰나요? | 상세 | |
| 준비물 | 상세 | |
| 프롬프트 또는 파일 | 상세 (복사·다운로드 대상) | A4 |
| 사용 순서 | 상세 | A5 |
| 예시 결과 | 상세 (별도 탭 또는 구역) | A5 |
| 주의할 점 | 상세 | A5 |
| 업데이트 날짜 | 상세 | 목록 카드에는 올리지 않음 |

## 5. 권한 표시 (무료 / 유료 / 특정 코호트 전용)

- 카드마다 권한 배지(무료 / 유료 / 코호트)를 보여준다. PRD §6-3 카드 항목.
- free 역할은 샘플 프롬프트를 쓸 수 있고 유료 자료는 미리보기까지다 (PRD §7-2). 접근 권한이 없는 카드는 목록에서 숨기지 않고 잠금 표시로 보여주며, 유료 전환 안내를 붙인다 (작업자 확정).
- 코호트 전용 카드는 그 코호트가 아닌 유료 회원에게도 잠금 표시로 보여준다 (작업자 확정).
- paid·seller 역할은 "일부 또는 전체 접근"이다 (PRD §7-3).
- 데이터 모델의 `access_level` 필드가 이 값에 대응한다 (PRD §8 SkillCard).

### 5-1. 잠금 카드의 화면 상태

- 잠금 표시: 접근 권한이 없는 카드에 자물쇠 표시를 올린다. 스킬명, 카테고리, 난이도, 권한 배지는 그대로 보인다.
- 유료 전환 안내: 무료 회원에게 잠긴 카드에는 유료 전환을 안내하는 문구를 함께 보여준다.
- 코호트 전용 카드가 그 코호트가 아닌 유료 회원에게 잠겨 보일 때도 같은 잠금 표시를 쓴다.
- 잠금 카드를 눌렀을 때 어떤 화면으로 이어지는지는 PRD에 없어 이번 설계에서 정하지 않는다.

## 6. 분석 문서 반영 항목 위치

| 항목 | 반영 위치 |
|---|---|
| A1 카드 목록 구조, 스킬명·카테고리 태그 | §3 (1~3), §4 |
| A2 검색, 태그 필터 (칩 줄 + 드롭다운) | §3 (1~2) |
| A3 난이도 작은 태그 | §4 |
| A4 복사 버튼, 파일 다운로드 (하단 고정 버튼) | §3-1 |
| A5 상세 탭 구획, 예시 결과 | §3-1, §4 |
| A6 관련 미션 카드형 링크 | §3-1 |
| A7 결과 없음 빈 화면 | §7 |

## 7. 제안: 결과 없음 빈 화면 (A7)

이 항목은 PRD §6-3에 없는 추가 제안이다. 검색어나 필터 조합에 맞는 스킬이 없을 때 목록 자리에 안내 문구를 보여주고, 필터를 풀어 보도록 유도한다. PRD 필수 기능이 아니므로 G2 확인 때 채택 여부를 정한다.

## 8. 확정 사항 요약

- guest, admin은 스킬 라이브러리를 보지 않는다. roles는 free, paid, seller.
- 접근 권한이 없는 카드는 숨기지 않고 잠금 표시 + 유료 전환 안내로 보여준다.
- 코호트 전용 카드는 그 코호트가 아닌 유료 회원에게도 잠금 표시로 보여준다.
- 목록 카드에는 스킬명, 카테고리, 난이도, 권한 배지(무료/유료/코호트)만 올린다. 추천 대상, 사용 도구, 업데이트 날짜는 상세에 둔다.

```json
{
  "screens": [
    {
      "screen": "스킬 라이브러리",
      "kind": "library",
      "roles": ["free", "paid", "seller"]
    }
  ]
}
```
