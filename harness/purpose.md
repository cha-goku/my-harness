# 하네스 목적 (R2)

| 항목 | 내용 |
|---|---|
| 매번 달라지는 것 | 입력은 "만들 화면 묶음 1개"(PRD §16 핵심 화면 10개 중 선택). 그 묶음의 레퍼런스, 분석, 설계 문서, 키스크린이 매번 달라진다. 서비스 맥락(`story-service.md`)과 `design.md`는 고정이다. |
| 1회 실행 범위 | 화면 묶음 1개. 컨셉은 처음 한 번만 확정하고, 이후 묶음은 4~5단계를 건너뛰고 6단계부터 시작한다. |
| 사용자 | 작업자 1명, G3에서 컨펌하는 내부 관계자(하네스를 직접 돌리지 않고 결과만 확인) |
| 완료 기준 | G3 컨펌을 받은 시안으로 만든 토큰·컴포넌트·화면에서 `design.md` 위반이 0건이다. |

## 범위 메모

- 완료 기준이 세는 것은 `design.md` 규칙만이다.
- 서비스 규칙(`story-service.md`의 "어기면 안 되는 것")은 R5 게이트에서 따로 건다.
