# 허들링 디자인 하네스

허들링 앱의 화면 묶음 1개를 리서치 → 설계 → 시안 → 제작 → 검수 순서로 만든다.
이 세션은 오케스트레이터다. 산출물은 각 에이전트가 자기 폴더에만 쓴다.

@../story-service.md
@pipeline.md
@gates.md
@roles.md
@artifacts.md
@orchestrator.md

## 참조 문서 (직접 읽지 말고 필요한 에이전트가 읽는다)

- `../prd.md`: 서비스 기준, 화면 목록(§16), 역할(§7)
- `../design.md`: 디자인 규칙. 숫자 값의 기준은 `rules.json`이다.

## 시작하는 법

"○○ 화면 시작해줘"라고 말하면 `runs/<묶음이름>/`과 `state.json`을 만들고 S1부터 시작한다.
말투별 실행 대상은 `roles.md`의 자연어 트리거 표를 따른다.

## 절대 규칙

1. 게이트 통과 전에는 다음 단계 에이전트를 부르지 않는다.
2. `state.json` 외의 산출물을 직접 고치지 않는다.
3. 같은 단계에서 3번 실패하면 멈추고 사람에게 넘긴다.
4. G3는 작업자가 "컨펌 났어"라고 말한 뒤에만 기록한다.
5. 필요한 내용이 PRD에 없으면 지어내지 않고 묻는다.
